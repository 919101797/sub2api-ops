# 系统架构

独立运维服务读取 Sub2API 管理接口和 PostgreSQL，在自己的状态、数据库模式和媒体目录中保存数据；禁止修改或派生 Sub2API 镜像。

## 组件

| 组件 | 端口 | 职责 |
| --- | --- | --- |
| `operations-console` | `3002 -> 8080` | Fastify、React、自动化、分析、HTTP 审计 |
| `ws-audit-relay` | `3003 -> 8090` | HTTP 用户请求大小网关、WebSocket 转发、持久发件箱、流式审计投递 |
| `sub2api-runtime-control.service` | 本机 Unix socket | 白名单修改 Sub2API 连接池及内存，持久化与失败恢复 |
| `sub2api-resource-monitor.service` | 无网络监听 | 宿主机每 15 秒独立采样，SQLite 保留 7 天 |

代码：`routes.ts` 管理接口；`auth.ts` 会话；`automation/` 重置与容量；`analytics.ts` 聚合；`prompt-audit/` 输入审计；`ws-relay/` 实时中继；`resource-monitor/` 只读资源查询；`shared/contracts.ts` 与 `shared/resources.ts` 前后端契约。

## 接口

| 范围 | 作用 |
| --- | --- |
| `/health` | 自动化健康 |
| `/ops/api/auth/*` | 密码、TOTP、OAuth、退出 |
| `/ops/api/bootstrap`、`dashboard` | 管理员、配置、账号、任务、活动 |
| `/ops/api/accounts/:accountKey/analytics` | 日、周、月、周期分析 |
| `/ops/api/prompts*` | 审计列表、详情、会话、图片、清理、解封 |
| `GET/PUT /ops/api/request-limits` | 管理员设置默认请求上限、用户例外、大请求阈值及通道数 |
| `/ops/api/run`、`config` | 手动任务与配置 |
| `GET/PUT /ops/api/resources/runtime` | 管理员读取及提交运行参数，异步应用、版本冲突保护 |
| `/ops/api/resources` | 管理员只读查询独立资源历史，最多 480 个保留尖峰的时间桶 |
| `/internal/prompts/capture*` | 共享密钥保护的内部采集 |

会话只允许启用中的管理员；令牌保存在加密 `HttpOnly` Cookie，生产使用 `Secure`、`SameSite=Strict`、路径 `/ops`。登录接口限流为 15 分钟 8 次。

## 数据流

周期重置：首次建基线；`reset_at` 明确前移且有用量下降或自然到期佐证后，先持久化订阅清单，再逐项重置并记录进度；重启续跑，同窗口不重复。

容量同步：`周期容量=standardCost/使用率`，按账号配置扣除固定 USD 或周期容量百分比对应的预留金额，再除以 `shareCount`；达到阈值才估算，每个整数使用率桶取首样本，最近 5 桶取中位数，差异不足阈值不写入。账号预留模式、预留值或份数变化时立即使用已有样本重算。

控制台实时数据由 TanStack Query 共享与去重；仪表盘在可见页面中每 60 秒刷新，后台标签页停止轮询。输入健康首次进入时加载默认结果，之后由管理员点击查询、翻页或完成解封操作时刷新，不做周期轮询；筛选控件只编辑草稿，点击查询后才替换当前查询条件。列表 SQL 把时间边界下推到审核日志和 Ops 记录两个来源，并让列表/计数、汇总/趋势各自共享一次去重结果。无搜索词时去重阶段仅读取索引字段，分页后再对当前页补齐正文摘要、媒体数和用户状态，避免 30 天查询物化完整正文。仪表盘触发的账号基础设施查询另有 60 秒服务端缓存，并以单个在途任务合并并发刷新。

用户峰谷限流策略在开启时每 60 秒通过既有只读账号查询 `users` 的 ID、状态、并发和 RPM，独立单连接池及 3 秒 SQL 超时，不加载管理员用户列表附带的历史账单最后使用时间；不缓存当前限制，对照后仅通过官方接口批量写入有差异的活跃用户。调度与容量、重置任务错峰启动。

账号分析只读官方既有表，使用单连接池；相同账号、分组和范围合并在途读取并共享成功结果 30 秒，保留结果中的实际统计时间边界，最多缓存 32 项，失败不缓存。没有新增或修改 Sub2API 表、索引及迁移，也不修改官方镜像和程序。

审计：HTTP 由 Nginx 后台镜像；WebSocket 先写本地发件箱再原样转发。只保存 `input` 最后一项；用户输入关联审核，续跑上下文标记无需审核。文本先脱敏，最多 1,000,000 字符；图片仅收 PNG/JPEG/WebP/GIF `data:`，单张 8 兆、最多 4 张、合计 12 兆，不下载外部网址。会话只保存显式标识的 SHA-256 指纹。

## 持久化与故障

| 数据 | 位置 |
| --- | --- |
| 配置 | `/app/config.json`，格式版本 11 |
| 运行状态 | `/data/state.json`，格式版本 2 |
| 图片 | `/data/prompt-media` |
| 请求大小策略 | `/data/request-limits/policy.json`，控制台写入、网关只读 |
| 待投递消息 | `/data/outbox` |
| 独立资源历史 | 宿主机 `/var/lib/sub2api-resource-monitor/metrics.sqlite3`，控制台只读 `/resource-monitor` |
| 审计记录 | PostgreSQL `sub2api_ops` |

任一自动化任务最近失败时控制台健康接口返回 `503`，Docker 健康检查仍将 `200/503` 都视为进程可达，避免上游任务降级阻断 WS 中继启动。中继健康接口返回连接数和发件箱用量；控制台不可用时退避重投，发件箱无法写入时关闭连接。具体行为和测试见[规格索引](../specs/README.md)。

运行参数控制器独立运行在宿主机，以 root 操作固定路径的 Sub2API 编排。控制台只挂载 `/var/lib/sub2api-runtime-control:/runtime-control:ro` 并连接 `control.sock`（root:1000，0660），不获得 Docker API。输入严格限制为版本哈希、连接数和内存，操作人由管理员会话注入；不接受路径或命令。控制器先保存私有备份与操作状态，再原子更新编排；连接池改变时保留当前官方程序版本并重建单个服务，内存单独改变时执行在线更新。健康或实际值校验失败后恢复原编排、原程序和内存，人工并发编辑则保留人工配置并报告恢复失败。控制器重启会恢复未完成操作。Sub2API 暂时不可达时鉴权返回 503 且保留会话；凭据真正失效仍返回 401/403。

余量自动再均分复用容量同步任务，按账号独立开关，同一账号的容量和重置操作串行。`automation/redistribution.ts` 在发现有效成员用完当前周限后，扣掉已用标准成本与预留，将估算余量按分配份数等额追加到全部目标分组。每轮先存绝对目标、触发成员用量与完成清单，写入后逐项记录；重启或响应丢失后对同一目标继续，不生成重复增量。当前周期追加下限独立保存在账号状态中，普通估值不会覆盖，关闭不回收已发额度；新周期通过重置任务的持久计划先恢复基础周限，再重置成员用量。余额估算不等同于上游精确可用配额，且不自动使用重置卡。

用户请求大小由独立原子策略文件管理，不修改原自动化 `config.json`。网关每个请求读取策略，通过权限受限的 `resolve_api_key` 函数获取真实用户；连接池最多 2 个，身份查询 1.5 秒超时，依赖不可用时返回 503。HTTP 无固定上传名额，完整落盘校验后发送固定内网 Sub2API，不解析 JSON、不重试模型调用，响应流式回传；Responses SSE 客户端等待响应头时每 10 秒注释保活，晚到错误终止为 SSE error，普通 JSON 与 compact 保留 HTTP 语义。完成日志只含关联标识、字节数、状态与分阶段耗时；所有标准入口及官方根路径别名由 Nginx 分流。WS 握手按用户额度限制接收器，较高额度连接预占全局通道，策略变更以 1012 要求重连。发件箱格式为四字节元数据长度、小 JSON 元数据和原始输入字节；列表只读头部，投递按偏移读取文件流，原文不进入 JSON 包装。
