# 功能-007：WebSocket 审计中继

状态：当前实现　范围：实时协议

目标：原样转发 WebSocket，同时确保每个客户端输入先持久化、入库确认后再删除。

## 规则

- 路径、查询、鉴权头、子协议和帧内容不改写；连接编号加递增序号形成审计编号。
- 消息先原子写入权限受限的发件箱再转发；写入失败即关闭连接。
- 控制台成功确认后删除；失败则退避重试且不阻断已建立连接。
- 发件箱默认上限 512 兆；消息、缓冲和握手均有限制；健康接口返回连接和容量。

## 场景

| 编号 | 假如 | 当 | 那么 |
| --- | --- | --- | --- |
| 场景-007-01 | 双端已连接 | 客户端发送多轮 | 帧原样到达，每轮先落盘再投递 |
| 场景-007-02 | 消息待投递 | 控制台确认 | 只删除对应文件 |
| 场景-007-03 | 控制台暂不可用 | 投递失败 | 保留并退避重试，继续转发 |
| 场景-007-04 | 发件箱无法写入 | 收到消息 | 不转发并关闭连接 |
