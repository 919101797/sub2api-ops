# 功能-012：用户请求大小限制

状态：已实现　范围：Ops 设置、HTTP 网关、WebSocket 中继

## 规则

- 默认 30 MiB，管理员可在 Ops 设置 1–100 MiB；按 Sub2API 用户 ID 单独覆盖，同一用户的全部 API Key 共用设置。身份通过已有数据库函数解析，不信任客户端提交的用户 ID。
- HTTP 所有 `/v1/` 请求（含 Responses、compact、Chat Completions）与 WebSocket 输入都执行限制；按解压后的实际完整请求/消息字节数计算，恰好等于上限允许，超出返回 HTTP 413 或 WS 1009，不裁剪内容。
- Ops 保存原子持久化并校验版本，冲突返回 409；相同设置（包括只改变用户例外顺序）保存不改修订、保存时间和操作人，也不重复记录变更审计。新 HTTP 请求、新 WS 连接立即读取新值。已有 WS 连接仅在自身大小上限或大请求通道归属变化时，于下一条输入前以 1012 关闭并要求重连；只改并发数或其他用户不打断无关会话。
- 全局基础设施硬上限 100 MiB，包括 Sub2API 入站 WS 的 `GATEWAY_OPENAI_WS_CLIENT_READ_LIMIT_BYTES=104857600`。业务上限只由网关收紧；Sub2API 的最终鉴权和额度检查仍执行。无效 Key 返回 401，身份数据库或策略不可用返回 503，不放宽限制。
- HTTP 通过有背压的流写私有临时文件，完整校验后才发送上游，成功、失败和取消均清理文件。不设置额外的固定上传并发名额，不因正在上传的小请求数量返回 429；超阈值大请求只使用 Ops 配置的大请求通道。gzip/zstd/br 输入按解压后的字节限制，未声明长度和 chunked 请求也检查实际字节；不重复发送模型请求。
- Responses 流式客户端明确声明 `Accept: text/event-stream` 时，网关在等待 Sub2API 响应头期间每 10 秒发送 SSE 注释保活，避免边缘代理空闲超时后重复提交。鉴权、大小、并发校验仍在保活前完成；上游响应头到达即交还原始流，不重复发送请求。保活前的错误保留 HTTP 状态；保活后上游 HTTP 错误或断连转换为终止 SSE `error` 事件，不能把错误 JSON 拼入成功流。非 SSE 请求和 compact 不提前提交响应。
- HTTP 完成日志只记录关联 ID、用户 ID、正文长度、鉴权/上传校验/上游响应头等待/响应/总耗时、上游状态和是否保活，禁止写入 Key、查询参数、正文或上游错误正文。
- 大请求通道只按管理员设置的并发数计数，不额外设置合计 100 MiB 的预占限制。中继容器 384 MiB、Node 堆 96 MiB；每个 WS 客户端落盘与转发完成前暂停读取，避免同连接堆积多份大消息。
- 大请求阈值默认 30 MiB，可设置 1–100 MiB；大请求并发默认 1，可设置任意正整数，前后端不设业务最大值。HTTP 超阈值请求在转发前占用通道，直到上游结束/取消释放；无可用通道返回 429 和 Retry-After，不排队。超过阈值额度的 WS 连接在握手前占用通道，连接关闭释放，防止多连接同时缓冲大帧。
- WS 原文持久化使用独立元数据和原始消息文件格式（单文件头部加原始字节），投递流式读取，不把整个发件箱加载进内存。部署前发件箱须为空；不迁移旧格式或删除未确认消息。
- 审计正文阈值仍独立为 16 MiB，超限沿用跳过正文采集的规则，不影响模型请求。网关不记录 API Key、URL 查询参数或正文，临时文件权限 0600。

## 场景

| 编号 | 假如 | 当 | 那么 |
| --- | --- | --- | --- |
| 场景-012-01 | 默认 30，用户 A 为 70 | A 的两个 Key 与普通用户分别发送请求 | A 都执行 70，普通用户执行 30；伪造用户头无效 |
| 场景-012-02 | 用户上限 1 MiB | 发送等于上限及多一个字节的请求，含 chunked/gzip | 等于上限原样到达上游，超限 413，上游不收到该请求 |
| 场景-012-03 | 大请求通道数为 1，已有大请求未结束 | 另一大请求到达、普通小请求到达 | 第二个大请求 429，小请求仍可用；取消后通道释放 |
| 场景-012-04 | 管理员修改默认值与用户例外 | 保存、重启、并发提交旧版本 | 新请求和重启后使用新值，旧版本提交 409，未登录不能读写 |
| 场景-012-13 | 已有 WS 会话 | 重复保存相同设置、重排例外、只修改其他用户或并发数 | 相同设置修订和元数据不变，无关会话正常续跑；本用户大小或通道归属变化仍重连 |
| 场景-012-05 | Key 无效或身份查询失败 | 请求模型 | 分别 401/503，不把正文送入模型，不泄漏 Key |
| 场景-012-06 | WS 用户额度高于大请求阈值 | 多连接、发送超限消息、修改策略 | 超额连接 429，超限消息 1009；策略修改后旧连接 1012，新连接按新值 |
| 场景-012-09 | 已有 8 个小请求上传完成但模型仍在返回 | 第 9 个小请求到达，或早先客户端取消 | 新请求正常转发；取消请求释放对应资源，不受固定上传名额限制 |
| 场景-012-12 | 已有 8 个小请求仍在上传 | 第 9 个请求上传并完成，随后其余请求完成 | 所有请求正文原样到达上游，不因固定上传名额返回 429，完成后临时文件清理 |
| 场景-012-10 | Responses SSE 客户端等待上游响应头超过 10 秒 | 上游稍后成功、返回错误或客户端取消 | 等待期间收到注释保活，成功流字节原样；晚到错误终止为 SSE error；取消释放连接、文件和通道，且只发起一次上游请求 |
| 场景-012-11 | 非 SSE 或 compact 请求等待上游 | 上游返回 429 或 JSON | 保留原 HTTP 状态、Retry-After 和正文，不提前提交响应 |
| 场景-012-08 | 管理员将大请求并发设为 5，两个用户各 65 MiB | 保存并重新读取，多个大额 WS 连接建立 | 设置 5 持久生效，两个 65 MiB 连接可同时建立；只在达到已配置通道数时返回 429，关闭后释放 |
| 场景-012-07 | WS 消息较大或投递失败 | 落盘、重启、重投 | 原始字节不变、内存不复制大 JSON，确认后才删除 |
