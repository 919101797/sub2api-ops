# 功能-010：SSE 出口压缩

状态：当前实现　范围：Nginx Responses 出口与客户端本机代理

目标：不修改 Sub2API 源码和镜像，压缩服务器发往客户端的 HTTP Responses 正文，保留流式、审计与 WebSocket 链路。

## 规则

- Nginx 只在 HTTP Responses location 按 `Accept-Encoding` 协商 gzip，等级 3，关闭代理响应缓冲；不压缩审计镜像子请求。
- 本机代理只监听 `127.0.0.1`，固定 HTTPS 上游，不存储密钥或正文、不重试模型请求；使用 Node.js 自带的 HTTP、TLS 和 zlib。
- 本机代理请求 gzip 响应，边接收边解压并移除压缩后的长度和编码头；WebSocket 握手及帧直接转发，保留现有协商。
- Codex 上传的 gzip/zstd 请求先在本机解压，重算 Content-Length，再进入现有 HTTP 审计与 Sub2API；这项能力不节省上传流量。
- 单次上传及解压后正文均不得超过源站的 100 MiB 上限；拒绝浏览器跨站请求与任意上游转发。
- 客户端关闭立即取消上游；不因客户端在模型完成后关闭而重试。压缩流结束不代表模型完成，模型终止事件仍由 Codex 校验。
- 客户端配置仅替换所选供应商 base_url，保持密钥、模型、透传及 WebSocket 设置；macOS 使用 LaunchAgent 常驻。

## 场景

| 编号 | 假如 | 当 | 那么 |
| --- | --- | --- | --- |
| 场景-010-01 | 上游逐事件输出 gzip SSE | 本机转发 | 第一事件在流结束前到达，中文与工具事件字节一致 |
| 场景-010-02 | Codex 上传 zstd/gzip JSON | 转发至服务器 | 审计收到明文 JSON 与准确长度，认证头保持一致 |
| 场景-010-03 | 客户端取消或上游损坏 | 正在输出 | 上游及时关闭或下游报错，不把断流转成正常结束，不自动重试 |
| 场景-010-04 | 上游返回未压缩正文或 HTTP 错误 | 转发 | 保留状态和正文 |
| 场景-010-05 | 现有客户端使用 WebSocket | 通过本机代理 | 握手、帧、关闭与压缩协商保持可用 |
| 场景-010-06 | 跨站、错误 Host、未授权或超大请求 | 访问本机代理 | 拒绝且不向上游发送 |
