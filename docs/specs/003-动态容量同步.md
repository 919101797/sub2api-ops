# 功能-003：动态容量同步

状态：当前实现　范围：额度自动化

目标：用实际使用率与成本估算周期容量，稳定同步目标分组周限。

## 规则

- `周期容量=standardCost/(usedPercent/100)`；每个账号可按固定 USD 或周期容量百分比计算预留金额，扣除后再除 `shareCount`，金额保留两位。
- 低于阈值只采样；每个整数使用率桶取首样本，最近 5 桶估算取中位数。
- 首个有效样本可估算；时间抖动保留稳定值；写入差异不足阈值则跳过。
- 账号的预留模式、预留值或分配份数变化后，下一次同步立即用已有样本重新估算，不等待使用率进入新桶。
- 固定分组不可作为目标，同一分组不可归属多账号。

- 每个账号独立设置“余量自动再均分”，默认关闭。开启后，任一有效成员用尽当前分组周限时，按 `max(0, 周期估算容量 - 账号本周期已用标准成本 - 预留金额) / 分配份数` 给所有目标分组追加相同金额；按美分向下取整，不重置成员已用量。
- 按容量同步间隔检查，同一使用率桶也检查追加；没有稳定估值、周限不限量、成员用量不可确认、新周期订阅重置未完成时不追加。上游额度已达 100% 或剩余不足每份 0.01 USD 时停止追加。
- 已追加的本周期周限作为下限，普通容量同步不能覆盖；关闭只停止后续追加，保留本周期已发额度。进入新周期后清除上一周期的追加下限。
- 每轮先持久化绝对目标及成员触发用量，再逐分组写入、逐项记录完成。失败或重启只补写未完成目标；不重算为新一轮，不因重复轮询重复发放。相同触发成员没有新增用量时不再次触发。
- 可分配余额来自既有容量估值和已用成本；预留金额始终从本轮计算中扣除。界面明确展示估算性质，不承诺上游物理配额的精确余额。不会自动使用上游重置卡。

## 场景

| 编号 | 假如 | 当 | 那么 |
| --- | --- | --- | --- |
| 场景-003-01 | 样本和配置有效 | 运行 | 计算并更新目标分组 |
| 场景-003-02 | 使用率低于阈值 | 运行 | 只保存观测 |
| 场景-003-03 | 时间抖动或同一整数桶 | 运行 | 沿用稳定估算 |
| 场景-003-04 | 与现值差异过小 | 运行 | 不调用写接口 |
| 场景-003-05 | 两个账号配置不同固定预留金额 | 运行 | 分别扣除各自预留金额后计算目标周限 |
| 场景-003-06 | 账号预留模式、预留值或份数已修改 | 在同一使用率桶再次运行 | 立即重新估算并应用新配置 |
| 场景-003-07 | 账号选择百分比预留 | 估算周期容量 | 按周期容量乘以百分比计算实际预留 USD，再计算可分配金额和每份周限 |
| 场景-003-08 | 一个账号开启、另一个关闭，存在额度用完的成员 | 容量同步 | 只为开启账号的所有目标分组追加同样金额，并保持已用量 |
| 场景-003-09 | 估算容量 1000、已用 400、预留 100、分 3 份，成员已用完 | 检查追加 | 每份追加 166.66，记录本轮和目标周限；再次读取同样用量不重复追加 |
| 场景-003-10 | 已完成一轮，后续有成员消耗新增额度后再耗尽 | 再次检查 | 按新的余额再次均分，正常同步不会把周限调回基础值 |
| 场景-003-11 | 余额不可分、上游已满、缺少估值或新周期尚未重置 | 检查 | 显示等待或停止原因，不追加、不清空任何用量 |
| 场景-003-12 | 两个分组只成功写入一个，随后进程重启 | 再次同步 | 沿用原轮次绝对目标，只补写未完成分组，累计金额不重复增加 |
| 场景-003-13 | 本周期已追加后关闭，或上游进入新周期 | 同步 | 关闭停止追加且保留本周期已发额度；新周期恢复基础分配，不继承旧周期追加 |
